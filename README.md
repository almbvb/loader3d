# Loader3D — интерактивное 3D-планирование загрузки фуры

Веб-приложение для раскладки грузов в кузове фуры/сцепки: полупрозрачный кузов с размерными линиями,
док (зона накопления) у задних дверей, перетаскивание грузов мышью и пальцем с гравитацией, коллизиями
и магнитной привязкой. В одной схеме может быть несколько машин, грузы можно кантовать, а загораживающие
обзор грузы — делать прозрачными.

Стек: **React 19 + TypeScript + three.js + zustand**, интерфейс — **Tailwind CSS 4 + shadcn/ui** (Radix,
иконки lucide), маршруты — React Router, запросы — TanStack Query; сборка — Vite, тесты — Vitest.
Бэкенд ([backend/](backend)): **Python 3.14 + FastAPI + SQLAlchemy 2 (async)**, SQLite в разработке, Postgres в проде.

```bash
npm install
npm run dev        # http://localhost:5173 (нужен запущенный бэкенд — см. «Бэкенд»)
npm test           # юнит-тесты ядра (коллизии, гравитация, магниты, перемещение стопок)
npm run build      # проверка типов + production-сборка в dist/
```

Для работы в браузере запускаются оба процесса: `cd backend && uv run python -m app --reload` и
`npm run dev`; Vite проксирует `/api` на бэкенд. Вход, регистрация и схемы — через API.

## Деплой (Docker)

На сервере нужны только Docker и Docker Compose v2 — Node.js и Python не нужны, сборка идёт внутри
образов (с прогоном тестов). Три контейнера:

- `web` — [Caddy](https://caddyserver.com): статика фронтенда, HTTPS, проксирует `/api/*` в `api`;
- `api` — бэкенд, при старте сам применяет миграции БД;
- `db` — Postgres, наружу не публикуется, данные в томе `postgres_data`.

```bash
git clone https://github.com/almbvb/loader3d.git && cd loader3d
cp .env.example .env     # задать JWT_SECRET и POSTGRES_PASSWORD (openssl rand -hex 32), остальное по желанию
docker compose up -d
```

Репозиторий приватный: для `git clone` на сервере нужен deploy key (SSH) или токен GitHub.
Обновление: `git pull && docker compose up -d --build`. Логи: `docker compose logs -f`.
Если сервер развёрнут до появления бэкенда — перед обновлением добавить в `.env` новые переменные
из `.env.example` (без `JWT_SECRET` и `POSTGRES_PASSWORD` compose не запустится).

Резервная копия БД: `docker compose exec db pg_dump -U loader3d loader3d > backup.sql`,
восстановление: `docker compose exec -T db psql -U loader3d loader3d < backup.sql`.

Все настройки — в `.env` (описание каждой — в `.env.example`):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SITE_ADDRESS` | `:80` | Домен (`loader.example.com`) → автоматический HTTPS от Let's Encrypt; `:80` → просто HTTP |
| `HTTP_PORT` / `HTTPS_PORT` | `80` / `443` | Порты на хосте, можно с IP: `127.0.0.1:8080` |
| `COMPOSE_PROJECT_NAME` | `loader3d` | Префикс имён контейнера, образа и томов |
| `JWT_SECRET` | — (обязательно) | Ключ подписи токенов, 32+ случайных символа; смена разлогинивает всех |
| `ACCESS_TOKEN_TTL_MINUTES` / `REFRESH_TOKEN_TTL_DAYS` | `15` / `30` | Время жизни access-токена и сессии без активности |
| `REGISTRATION_OPEN` | `true` | `false` — новые аккаунты создавать нельзя |
| `COOKIE_SECURE` | `true` | `false` только если сайт открывают по голому HTTP (иначе вход не переживёт перезагрузку) |
| `POSTGRES_PASSWORD` | — (обязательно) | Пароль БД, применяется при первом создании базы |
| `POSTGRES_DB` / `POSTGRES_USER` | `loader3d` / `loader3d` | Имя базы и пользователя |
| `LOG_MAX_SIZE` / `LOG_MAX_FILE` | `10m` / `3` | Ротация логов контейнеров |
| `NODE_VERSION` / `CADDY_VERSION` / `PYTHON_VERSION` | `24` / `2` / `3.14` | Версии базовых образов (после смены — `--build`) |
| `POSTGRES_VERSION` | `18` | Мажорная версия Postgres (18+; смена у существующей базы — через dump/restore) |

Типовые варианты:

- **Отдельный сервер с доменом** — DNS-запись домена указывает на сервер, порты 80 и 443 открыты:
  `SITE_ADDRESS=loader.example.com`. Сертификат выпускается и продлевается сам и хранится в томе
  `caddy_data` (его не удалять, иначе выпуск начнётся заново).
- **За существующим nginx/traefik** — `SITE_ADDRESS=:80`, `HTTP_PORT=127.0.0.1:8080`,
  `HTTPS_PORT=127.0.0.1:8443`, а во внешнем прокси — `proxy_pass http://127.0.0.1:8080`.
- **Просто по IP** — значения по умолчанию, приложение откроется на `http://<IP сервера>/`.

Схемы хранятся в аккаунте на сервере (в браузере — только настройки отображения). План, который
остался в браузере от версии без аккаунтов, главная страница предлагает сохранить как схему.

## Бэкенд (API)

Каталог [backend/](backend): FastAPI, SQLAlchemy 2 (async), Alembic, Pydantic. Всё под префиксом `/api`,
интерактивная документация — `/api/docs`, схема OpenAPI — `/api/openapi.json` (из неё можно генерировать
TS-типы клиента). Поля JSON — в camelCase, как во фронтенде.

Локально нужен [uv](https://docs.astral.sh/uv/) (`pip install uv` или установщик с сайта), Python 3.14 uv
найдёт или скачает сам:

```bash
cd backend
uv sync                          # зависимости в backend/.venv
uv run python -m app --reload    # миграции + сервер на http://127.0.0.1:8000 (SQLite: backend/loader3d.db)
uv run pytest                    # тесты (на временной SQLite; TEST_DATABASE_URL=postgresql+asyncpg://… — на Postgres)
uv run ruff check . && uv run ruff format --check .
```

`npm run dev` проксирует `/api` на `127.0.0.1:8000`, поэтому фронтенд в разработке ходит в API с того
же адреса, что и в проде. Настройки бэкенда — переменные окружения (или `backend/.env`):
`DATABASE_URL`, `DATABASE_PASSWORD`, `JWT_SECRET`, `ACCESS_TOKEN_TTL_MINUTES`, `REFRESH_TOKEN_TTL_DAYS`,
`REGISTRATION_OPEN`, `COOKIE_SECURE`, `CORS_ORIGINS`, `ENVIRONMENT` (см. [config.py](backend/app/config.py)).

Изменили модели в `app/models.py` — нужна миграция, которая работает и на SQLite, и на Postgres:
`uv run alembic revision --autogenerate -m "что изменилось"`, проверить файл в `migrations/versions/`.
Тест `test_migrations_match_the_models` падает, если миграции не совпадают с моделями.

### Эндпоинты

| Метод и путь | Что делает |
|---|---|
| `POST /api/auth/register` | Регистрация `{email, password, displayName?}` → вход (как login) |
| `POST /api/auth/login` | `{email, password}` → `{accessToken, expiresIn, user}` + cookie с refresh-токеном |
| `POST /api/auth/refresh` | По cookie: новый access-токен, refresh-токен ротируется |
| `POST /api/auth/logout` | Завершить текущую сессию (нужна только cookie) |
| `GET /api/auth/sessions` | Активные сессии (устройства): user agent, IP, последняя активность, `current` |
| `DELETE /api/auth/sessions/{id}` / `DELETE /api/auth/sessions` | Завершить одну / все остальные сессии |
| `GET /api/users/me`, `PATCH /api/users/me` | Профиль, смена `displayName` |
| `POST /api/users/me/password` | Смена пароля, остальные сессии завершаются |
| `DELETE /api/users/me` | Удаление аккаунта со всеми схемами (`{password}` в теле) |
| `GET /api/plans?q=&sort=-updatedAt&limit=20&offset=0` | Главная: схемы пользователя без содержимого (`vehicleCount`, `bodyCount`, `itemCount`, даты), поиск по названию, `sort`: `updatedAt`/`createdAt`/`name`, `-` — по убыванию |
| `POST /api/plans` | Новая схема `{name, data?}`; без `data` — пустая с еврофурой 13,6 м |
| `GET /api/plans/{id}` | Схема целиком: `data` — тот же `Plan`, что экспортирует фронтенд в JSON |
| `PATCH /api/plans/{id}` | Сохранить `{version, name?, data?}`; `409 version_conflict`, если схему уже изменили |
| `POST /api/plans/{id}/duplicate` | Копия `{name?}` (по умолчанию «… (копия)») |
| `DELETE /api/plans/{id}` | Удалить |
| `GET /api/health` | Проверка живости и связи с БД |

Ошибки: `{"detail": {"code": "...", "message": "..."}}` — `code` для логики клиента, `message` по-русски
для показа; ошибки валидации — стандартный ответ FastAPI `422`.

### Как клиенту работать с сессией

- **Access-токен** (JWT, 15 мин) — из ответа login/register/refresh, держать в памяти (не в localStorage)
  и слать в `Authorization: Bearer …`.
- **Refresh-токен** (JWT, 30 дней) — только в httpOnly-cookie `loader3d_refresh` с `Path=/api/auth` и
  `SameSite=Strict`: JavaScript его не видит, браузер шлёт его только на `/api/auth/*`.
- При загрузке страницы — `POST /api/auth/refresh`: 200 → пользователь вошёл, 401 → показать вход.
- На `401` с `code: "token_expired"` — один раз `refresh` и повторить запрос; если и refresh дал 401 —
  на экран входа.
- Каждый refresh выдаёт новый refresh-токен. Старый принимается ещё 30 секунд (несколько вкладок
  обновляются одновременно), позже — считается украденным, и сессия завершается для всех её копий.
- Logout и «завершить сессию» действуют сразу: каждый запрос проверяет, что сессия жива.
- Сохранение схемы — `PATCH` с `version` из последнего ответа; на `409` предложить перезагрузить схему.

Сервер проверяет структуру и диапазоны плана (размеры как в `core/presets.ts` и `core/item.ts`, вес груза
до 30 т и грузоподъёмность до 60 т — оба поля необязательны, до 10 машин по 1–3 кузова, до 5000 грузов,
уникальные id), но не физику: отсутствие пересечений по-прежнему обеспечивает `settle()` на клиенте.
План — `{vehicles, dockMode, items, nextSeq}`; схемы, сохранённые до появления нескольких машин (`bodies` вместо
`vehicles`), читаются как одна машина «Машина 1» — так же, как `parsePlan()` на клиенте.

## Что умеет

- **Аккаунты**: регистрация и вход, сессия переживает перезагрузку страницы; страница «Аккаунт» — имя,
  смена пароля, список устройств с завершением сессий, удаление аккаунта.
- **Главная — «Мои схемы»**: карточки схем (количество грузов и кузовов, когда изменена), поиск по названию,
  сортировка, создание с выбором транспорта, переименование, дублирование, скачивание JSON, удаление,
  импорт JSON.
- **Автосохранение**: каждое изменение схемы сохраняется на сервер через секунду; статус в шапке редактора
  («Сохранено» / «Сохранение…» / «Не сохранено» с повтором). Если схему сохранили в другой вкладке или на
  другом устройстве — диалог «Загрузить сохранённую / Оставить мою».
- **Транспорт**: шаблоны (еврофура, мега, реф, сцепка 7,7+8,2, контейнеры 20'/40', грузовики), длина/ширина/высота
  каждого кузова, кнопка «+ Прицеп» (до 3 кузовов). При изменении кузова грузы едут вместе с ним
  (привязка к передней стенке), грузы удалённого кузова переезжают на док.
- **Несколько машин** (до 10): «+ Машина» с выбором шаблона ставит новую машину рядом с остальными у той же
  рампы. Переключение — чипы в карточке «Транспорт» или клик по табличке с именем над кабиной: камера
  переезжает к машине, карточка, статистика, новые грузы и автозагрузка относятся к ней; выбор груза в другой
  машине делает активной её. У машины есть имя, её можно убрать (грузы переезжают на док, отмена — Ctrl+Z).
  **Зона накопления**: «Общая» — одна платформа вдоль всех машин, машины стоят плотно (5,2 м между осями), груз
  удобно перекладывать из машины в машину; «У каждой своя» — отдельный док за каждой машиной, у каждой свои грузы.
  При переключении грузы остаются у своей машины, а то, что не помещается рядом, переставляется на свободные места.
- **Грузы**: ввод Ширина / Высота / Длина, количество, название, типовые грузы (европаллета, финпаллета, IBC…),
  список с размерами и статусом («В кузове» / имя машины / «Док» / «За габаритами»), инспектор выбранного груза
  (размеры, название, цвет), поворот на 90°, дублирование, удаление.
- **Кантование** (включается переключателем «Кантовать» в инспекторе или в меню «Вид»): поворот на 90° вокруг любой
  оси — X (вдоль машины, груз ложится на бок), Y (вертикаль, как раньше) и Z (поперёк, груз встаёт на торец), всего
  шесть положений. Выключено — только вокруг вертикали. Автозагрузка кантованный груз не переворачивает обратно,
  а сама грузы не кантует. Повороты на произвольный угол не делаются: физика работает с прямоугольными объёмами.
- **Прозрачность грузов** (кнопка с глазом над сценой или меню «Вид»): «Перед выбранным» — грузы между камерой и
  выбранным грузом становятся полупрозрачными (по умолчанию); «Все загораживающие» — всё, за чем спрятаны другие
  грузы (рентген загрузки); «Все грузы» — кроме выбранного; «Выключена». Плотность — ползунком. Прозрачные грузы
  не дают тени, контур остаётся виден, переход плавный; нажатие на прозрачный груз берёт тот, что виден за ним.
  С несколькими машинами грузы соседних машин, закрывающие активную, прозрачны всегда (кроме «Выключена»).
- **Сцена**: размерные линии «как на чертеже» (подписи прячутся, если не помещаются), номера на грузах,
  размеры выбранного груза, виды 3D / сверху / сбоку / сзади, «показать всё», фиксация камеры.
- **«Подсвечивать выходы за грани»**: части груза за стенками/потолком кузова подсвечиваются красным
  объёмом, рёбра груза краснеют; счётчик в шапке и статистике.
- **Статистика**: заполнение кузова по объёму, LDM (занятые погонные метры от передней стенки), количество
  грузов в кузове / на доке / за габаритами.
- **Отмена/повтор** (Ctrl+Z / Ctrl+Y), экспорт плана в JSON и замена содержимого из JSON (отменяемо).
- **Экспорт в PDF** («Файл» → «Экспорт в PDF…», по выбранной машине или по всем — каждая с новой страницы):
  план загрузки для водителя и склада на A4 (альбомная или
  книжная) — виды сверху и сбоку с номерами грузов (ортографические, как чертёж, с линейками, или
  перспективные), список мест (одинаковые грузы одной строкой, что осталось на доке или вышло за габариты —
  цветом), итог по кузову (масса, места, объём, площадь пола, длина/ширина/высота: занято, максимум, остаток) и
  развесовка (центр тяжести против нормы). Режим «Пошаговая инструкция» добавляет порядок загрузки с выбранной
  стороны (сзади, сбоку справа/слева, сверху): груз ставится после того, на чём стоит, и после того, что дальше
  от проёма в его ряду; по картинке на шаг, уже загруженное — серым. PDF собирается в браузере (pdfmake, шрифт
  Roboto), библиотека подгружается только при экспорте.
- **Вес и грузоподъёмность**: вес у каждого груза (кг, у типовых грузов — типичный), грузоподъёмность у
  кузова (т, у шаблонов транспорта — своя). В статистике — вес кузова из грузоподъёмности и центр тяжести
  груза (ЦТ, % длины от передней стенки): зелёный — в безопасной зоне, жёлтый — нет.
- **Автозагрузка** («Загрузить в кузов»): грузы с дока раскладываются в кузов сами — тяжёлые на пол и ближе к
  середине, лёгкие сверху (только когда на полу нет места, целиком на опоре), каждый ряд прижат к борту так,
  чтобы груз не перекашивало, грузоподъёмность не превышается. Перед применением — предпросмотр: сколько
  встанет, вес и центр тяжести по кузовам, что и почему останется на доке. Можно переложить заново и то, что
  уже в кузове. Отменяется одним Ctrl+Z.
- **Редактор**: шапка — назад к схемам, название (переименование по клику), статус сохранения, отмена/повтор,
  меню «Вид» (размерные линии, номера, выходы за грани, магниты, ручки, единицы), «Файл», справка, кнопка
  панели грузов. Над сценой — карточка «Транспорт» (шаблон, размеры и грузоподъёмность кузовов, «+ Прицеп»,
  сворачивается), камера и статистика; справа — плавающая панель грузов (новый груз, автозагрузка, список,
  инспектор выбранного), её можно скрыть; на телефоне она открывается шторкой.

## Управление (без переключения режимов)

| Действие | Мышь | Планшет |
|---|---|---|
| Вращение сцены | тянуть по пустому месту | один палец по фону |
| Перемещение груза | тянуть груз (стопка на нём едет вместе) | палец на грузе |
| Только этот груз, без стопки | Alt + тянуть | — |
| Без магнитов | держать Shift | — |
| Панорама / масштаб | ПКМ / колесо | два пальца |
| Изменить размер | тянуть стрелки на гранях выбранного груза | то же |
| Приблизить к грузу | двойной клик | двойной тап |

Клавиши для выбранного груза: `R` — поворот 90° вокруг вертикали, `X` / `Y` / `Z` — вокруг оси X / Y / Z (при
включённом кантовании), `Del` — удалить, `Ctrl+D` — дублировать,
стрелки — сдвиг на 1 см (Shift — 10 см) по направлению взгляда камеры, `F` — показать, `Esc` — отмена перетаскивания.

## Архитектура

```
src/
  core/            чистая логика без three.js и React (покрыта тестами)
    types.ts         модель: Plan (машины, режим дока, грузы), Vehicle, CargoBody, CargoItem, Box, Orientation
    geometry.ts      AABB: пересечения, вычитание (части за габаритом), clamp к полу
```

### Как устроено контекстное взаимодействие

`InteractionManager` слушает `pointerdown` на контейнере канваса в фазе **capture**, то есть раньше
OrbitControls. Делается raycast: если под указателем груз (или ручка размера) — событие останавливается
(`stopPropagation`), камера его не видит, начинается перетаскивание; если пусто — событие уходит дальше в
OrbitControls и сцена вращается. Дополнительные пальцы во время перетаскивания игнорируются, а пальцы,
присоединившиеся к жесту камеры, остаются у камеры (щипок, панорама).

### Почему грузы не висят и не пересекаются

Высоту груза пользователь не задаёт. При перемещении группа ставится на высоту
`max(верх всех грузов под её основанием, 0)` — так она не может ни пересечь соседа, ни повиснуть.
После любого изменения выполняется `settle()` — проход «гравитации» снизу вверх, который гарантирует
отсутствие пересечений и висящих грузов для любого входного состояния (это проверяют тесты).
Магнит никогда не «запрыгивает» на соседа: вариант привязки принимается, только если не поднимает груз.

### Точки расширения

- **Поворот**: `Orientation` (`yaw` + `up` — какая своя сторона смотрит вверх) + `axisMap()` / `effectiveDims()` /
  `intrinsicDims()` / `rotate90()` в `core/orientation.ts` — все шесть положений с шагом 90° вокруг любой оси.
  Свободный угол потребует OBB-коллизий в `geometry.ts`/`physics.ts` — остальной код работает через `itemBox()`.
- **Изменение размеров на сцене**: уже работает push/pull граней (`core/resize.ts` + `scene/tools/ResizeTool.ts`):
  округление до 1 см, привязка к граням соседей и стенкам, упор в соседа, грузы сверху поднимаются гравитацией.
  Ввод точного значения с клавиатуры во время жеста — следующий шаг.
- **Новые жесты** (рамка множественного выбора, рулетка): реализовать `Tool` и добавить ветку в
  `InteractionManager.createTool()`.
